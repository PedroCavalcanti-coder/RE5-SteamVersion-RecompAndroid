# Making a recomp project public

Every project in this family says some version of *"bring your own disc; no
game files included"*. This is how to be sure that is true before you flip the
switch, and how to fix it when it is not.

Run `python tools/audit_repo.py ../yourproject` first. The rest of this
document is what to do about what it finds.

---

## The bar

Three things must not be in a public repo. Two are obvious and one is not.

**Game material.** The original binary, its DLLs, a disc image, extracted
assets. Nobody argues with this one.

**Lifted output.** The generated C. This is the one that gets missed, because
it looks like source we wrote and it sits in `src/`. It is not ours: lifting a
binary produces a derivative work of that binary, so the generated C carries
whatever licence the original does. This repo's own LICENSE says so. Publishing
it publishes the game's code in another form, just less legibly.

The bar is not theoretical -- it is what the already-public projects do.
Measured across gta, fury3, dinopark, crimsonskies, elfish, sof and civ:
**zero tracked lifted files**, in all of them. The `.gitignore` template here
already excludes `src/game/recomp/gen/` and `RecompiledFuncs/`.

**Either of the above, in history.** Deleting a file from HEAD does not
un-publish it. A public repo exposes its whole history and `git log -p` is one
command. This is the failure that looks fixed and is not.

### What is fine

Derived *metadata* is fine and normal: function addresses, vtable lists, IDA
exports, linker-map symbol tables, `analysis/*.json`. The public repos ship
plenty -- gta 7 files, crimsonskies 5, fury3 2. The line is between **facts
about the binary** and **a copy of it**. A list of addresses is a fact. The
instructions at those addresses are a copy.

Screenshots of your own port running are yours. Keep them in `docs/`, which is
where the auditor expects them; the same image file anywhere else reads as the
game's art.

---

## Stripping it

Removing the files from HEAD is not enough. Use `git-filter-repo`
(`pip install git-filter-repo`), which rewrites every commit.

**Do this on a fresh clone**, never on a working repo with unpushed commits or
uncommitted changes. The rewrite changes every commit hash after the first
affected one, so anything not pushed is orphaned.

```bash
git clone https://github.com/you/project.git project-clean
cd project-clean

python -m git_filter_repo --invert-paths \
    --path-glob 'src/seg*.c' \
    --path-glob 'src/recomp/gen/*' \
    --path-glob 'RecompiledFuncs/*' \
    --path-glob 'src/_dispatch.c'

# Verify: both numbers must be zero.
git ls-files | grep -cE 'seg[0-9]+\.c|recomp_[0-9]+\.c' || echo 0
git rev-list --objects --all | grep -cE 'seg[0-9]+\.c|recomp_[0-9]+\.c' || echo 0

python ../tools/tools/audit_repo.py .        # should say CLEAN
```

Then force-push, and tell anyone with a clone to re-clone rather than pull --
their history no longer matches.

Measured on one project (135 generated files across 60 commits): **20.6 MB ->
3.3 MB**, every commit preserved, every hand-written file intact. Check that
last part rather than assuming it:

```bash
git -C ../project-original ls-files > /tmp/before
git ls-files > /tmp/after
comm -23 <(sort /tmp/before) <(sort /tmp/after)   # only generated files here
```

Every file that list names should carry an `Auto-generated by` header. If one
does not, the glob was too wide.

## Order of operations

1. **Audit.** `python tools/audit_repo.py ../project`
2. **Add the `.gitignore` rule** so nothing new lands. Safe to do at any time;
   it does not untrack what is already there, and it does not disturb a relift
   in progress.
3. **Reach a clean stopping point.** No uncommitted changes, nothing unpushed.
   The rewrite is the one step that cannot be done around live work.
4. **Strip on a fresh clone**, verify, force-push.
5. **Re-audit.** Then flip public.

Steps 1 and 2 can happen whenever. Step 4 is the one to schedule.

---

## If `git fsck` reports corrupt objects

Fix this before rewriting anything: `filter-repo` walks every object, and a
damaged store turns a rewrite into a partial one.

```bash
git fsck --no-progress
```

If the remote is healthy, the cheapest repair is to re-clone and reapply local
work by hand -- but check what is only local first, because that is what you
are about to lose:

```bash
git log --oneline origin/main..HEAD    # commits that exist nowhere else
git status --short                     # and uncommitted work
```

A repo that is both corrupt and ahead of its remote needs the local commits
rescued (`git format-patch`, or copying the files out) before anything else
happens to it.
